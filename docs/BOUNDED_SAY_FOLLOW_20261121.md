## Purpose and evidence boundary

RCM physically proved **one** RIFT Live Say → Log.txt → editor → in-game Imports → SavedVariables path. This new companion **observes multiple *new* Say-format lines during one explicitly bounded Windows session** without typing into RIFT. It is a stepping stone toward reliable social-chat bridging, not automatic in-game chat reception.

- **Known syntax only:** HH:MM:SS: [Speaker] says: message, the November 21 game-observed format. Historical bracketed Guild/Party/Tell guesses are ignored.
- **Read-only:** Does not create or modify Log.txt, change logging, focus windows, send keys, touch the clipboard, or edit SavedVariables.
- **Startup boundary:** An existing log file is required. A first read establishes EOF without replay. A new message must be newline-terminated.
- **Session bounds:** Default 30 seconds and 20 Say messages. Options permit 1–300 seconds, polling every 25–1000 ms and 1–100 messages. Restarting is a new session, **not durable automatic replay**.
- **Privacy:** Default emits redacted metadata only. Explicit --prepare-import emits Base64URL editor commands that encode private sender/body data; treat as private.
- **Source integrity:** A log change, malformed/oversized line, or excess pending candidates aborts rather than silently accepting ambiguous history.
- **No delivery claim:** Prepared editor commands require separate validated submission and in-game acceptance; editorDeliveryVerified and diskSavedVerified remain false.
- **Physical provenance:** Syntactically recognized lines do NOT by themselves prove that the file originated from a running RIFT process.

## Commands (PowerShell on AMD-DESKTOP)

Check the actual RIFT Log.txt location. The user's DocumentsDirectory may be redirected by OneDrive; do not copy an example path literally. The file must already exist. If noncombat logging is off, RIFT's /log is a **toggle**, not an idempotent enable command.

Metadata-only monitoring:

    cd C:\work\RiftChatModern
    node .\tools\rcm-live-say-follow.cjs --path "C:\path\to\RIFT\Log.txt" --timeout-ms 60000 --poll-ms 100 --max-messages 10

Opt-in private editor batch *preparation* without sending anything:

    node .\tools\rcm-live-say-follow.cjs --path "C:\path\to\RIFT\Log.txt" --timeout-ms 60000 --max-messages 10 --prepare-import

--help prints all options. After started, a new actual Say line may yield a say_observed metadata record, then (only with opt-in) an rcm_manual_import record. The helper stops on timeout or message cap.

**Do not pipe arbitrary JSONL output into the Windows editor sender.** That sender expects exactly one validated RCM1-B64URL batch, a pinned target, and explicit focus/submission acknowledgments. This follower emits multiple JSONL metadata and batch records and never dispatches them.

## Testing and physical evidence

The isolated Node test file tests/test_live_say_follow.cjs covers argument bounds, stale-baseline exclusion, privacy, exact editor encoding, Guild-guess exclusion, truncation rejection, and file-source integrity. Fixtures use temporary synthetic logs. Real player names, log files and character SavedVariables are not committed.

**Physical read-only smoke test on AMD-DESKTOP:** The actual configured RIFT Log.txt existed at 85 bytes. The new tool established EOF at byte 85, completed nine polls during a one-second bounded trial, reported zero delivered messages and zero skipped messages, and stopped normally on timeout. No game input, focus change, or SavedVariables edit occurred. This proves startup and stale-record exclusion on the actual file, **not** a new live chat capture.

**A second newly typed live Say during this helper session is still needed** to establish a fresh physical capture via this new tool, apart from the previously physically accepted v0.2.23 one-message flow. The eight temporary-log tests also exercise rolling checkpoints against in-place rewriting of *recently appended* data.

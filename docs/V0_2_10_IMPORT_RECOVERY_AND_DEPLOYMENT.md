## Product goal

Rift Chat Modern is intended to reproduce much of RIFT's native social chat while providing modern searchable history, dependable input, and a reusable diagnostics/command interface for other RIFT repositories. v0.2.10 improves the previously developed **manual Windows-to-addon import**. Native RIFT chat remains unmodified as the fallback.

A manual import is **not** automatic say/tell/guild reception. It is a bounded, operator-pasted command that inserts an external candidate message with an explicit `[HOST? Channel]` label. The physical client's normal chat-log capture and host-to-addon automation are still not proven.

## Release changes

### Native chat: visible import progress

RIFT original chat can receive `/rcm import ID INDEX/TOTAL BASE64URL` lines generated by the Windows helper. In v0.2.9 the intermediate import receipts were shown only in the RCM footer, which was invisible while the RCM window was hidden. v0.2.10 now writes a colored native chat receipt **after each accepted chunk**, even while the RCM panel is closed. It also reports duplicates and completion without claiming native player-chat capture.

### New recovery/status commands

In RIFT's **original chat input**:

- `/rcm import status` — shows current pending ID, progress and import/reject/duplicate/cancel/expiry counters
- `/rcm import cancel` — discards only the incomplete transient chunk buffer; never clears saved RCM history
- `/rcm import help` — displays the supported import syntax

In **RCM's own editor**:

- `:host status` — same status information
- `:host cancel` — explicitly abandons a pending import

The public `RiftChatModernAPI.GetHostIngressStatus()` has an additive `cancelled` counter and expires a stalled transfer when status is requested, even if no subsequent chunk arrives. The 45-second time limit, one pending transfer, 12-chunk bound, UTF-8 validation, replay protection and existing saved-message schema remain unchanged. The interface version stays **1**.

### New reusable deployment helper

`tools/deploy_rcm.py` replaces ad hoc installation scripts:

- **Dry-run by default**; lists changes without writing anything
- Finds an existing RCM addon installation using supported Documents/OneDrive locations, or accepts `--target`
- Requires an exact expected hostname for `--apply`
- Verifies established installation identity, mandatory `.toc` fields, Environment, character-scoped SavedVariables, 6 RunOnStartup modules and order, and synchronization of manifest/Core/Main version strings
- Copies only changed source files, first backing up replaced installed files to gitignored `artifacts/deploy-backups`
- Writes via same-directory temporary files and atomic replacement, verifies all source/installed SHA-256 hashes, and attempts rollback if an error occurs
- Does not remove unknown installed files, alter character SavedVariables, send game input, reload the UI or start RIFT

**Dry-run**, from a PowerShell terminal in `C:\work\RiftChatModern`:

```powershell
& "C:\work\riftreader2\.venv\Scripts\python.exe" -B tools\deploy_rcm.py
```

**Explicit deployment**, after verifying the machine and destination:

```powershell
& "C:\work\riftreader2\.venv\Scripts\python.exe" -B tools\deploy_rcm.py --apply --expect-host AMD-DESKTOP
```

If a Windows user has multiple valid RCM installations, auto-discovery refuses to choose; supply `--target "C:\exact\RIFT\Interface\AddOns\RiftChatModern"`.
